LAB-004 // HTTP SECURITY HEADERS

REDUZIR. RESTRINGIR.
ENDURECER.

Laboratório local para comparar um servidor HTTP baseline com uma versão endurecida por políticas de segurança no nível dos headers.

Objetivo

Observar os headers HTTP originais, adicionar políticas de segurança e validar a resposta real do servidor com curl.

Ambiente

Debian em WSL 2, Python 3.13.5 e curl. O baseline foi executado em 127.0.0.1:8080 e a versão hardened em 127.0.0.1:8081.

ESCOPO: ambos os serviços foram vinculados ao loopback e usados somente no laboratório autorizado.

Baseline — 8080

curl -I http://127.0.0.1:8080/
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.13.5
Date: ...
Content-type: text/html
Content-Length: 66
Last-Modified: ...

O servidor baseline não enviava políticas modernas de segurança nos headers observados.

Hardening — 8081

curl -I http://127.0.0.1:8081/
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.13.5
Content-type: text/html
Content-Length: 66

X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; script-src 'self'

O mesmo conteúdo continuou respondendo com 200 OK, agora acompanhado pelas políticas configuradas.

Função dos headers

  • X-Content-Type-Options: nosniff — reduz MIME sniffing pelo navegador.
  • Referrer-Policy: no-referrer — impede o envio do referrer.
  • Permissions-Policy — restringe câmera, microfone e geolocalização.
  • Content-Security-Policy — define origens permitidas para recursos do documento.

Observação sobre CSP

CSP não deve ser tratada como um valor universal para qualquer aplicação. Uma política precisa refletir os recursos legítimos do site. Neste laboratório, a política foi propositalmente simples e adequada ao conteúdo estático local.

Conclusão

O experimento demonstrou um fluxo profissional básico de hardening: estabelecer baseline, aplicar uma mudança controlada, verificar o comportamento e documentar o resultado. O objetivo não é adicionar headers por checklist, mas entender qual risco cada política ajuda a reduzir.
