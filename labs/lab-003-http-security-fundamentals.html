LAB-003 // HTTP SECURITY FUNDAMENTALS

OBSERVAR. VALIDAR.
INTERPRETAR.

Laboratório local para estudar requisições HTTP, métodos, códigos de status e exposição indevida de arquivos. Todos os testes foram executados contra 127.0.0.1.

Objetivo

Entender a comunicação entre cliente e servidor HTTP usando curl e um servidor Python local, observando como diferentes métodos e recursos produzem respostas diferentes.

Ambiente

Debian em WSL 2, Python 3.13.5, curl e SimpleHTTPServer. O serviço foi vinculado exclusivamente a 127.0.0.1:8080.

ESCOPO: laboratório autorizado e isolado. Nenhum sistema externo foi alvo.

Descoberta de exposição

Inicialmente, o servidor foi iniciado no diretório home. O directory listing revelou arquivos como .bash_history, .bashrc e .profile. O serviço foi imediatamente interrompido e reiniciado em ~/cyberfoxys-lab.

Após a correção, somente o conteúdo destinado ao laboratório ficou disponível. A lição é sobre escopo de dados, não sobre uma vulnerabilidade inerente ao Python.

Resultados

01 // GET / — 200 OK
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.13.5
Content-type: text/html
Content-Length: 66

<h1>CyberFoxys LAB-002</h1>
<p>Authorized security laboratory.</p>
02 // HEAD / — 200 OK
HTTP/1.0 200 OK
Content-type: text/html
Content-Length: 66
Last-Modified: ...

Headers foram retornados sem o corpo HTML.

03 // OPTIONS / — 501
HTTP/1.0 501 Unsupported method ('OPTIONS')

O SimpleHTTPServer não implementa esse método nesse handler. Isso é uma característica do servidor, não uma vulnerabilidade por si só.

04 // GET /nao-existe — 404
HTTP/1.0 404 File not found
Content-Type: text/html;charset=utf-8

Conceitos aprendidos

  • 200 OK: a requisição foi atendida com sucesso.
  • 404 Not Found: o recurso solicitado não existe.
  • 501 Not Implemented: o servidor não implementa a operação solicitada.
  • GET vs HEAD: GET retorna representação do recurso; HEAD retorna metadados sem o corpo.
  • Directory listing: pode revelar arquivos quando o serviço é executado no diretório errado.

Conclusão

O LAB-003 demonstrou que analisar HTTP é mais do que olhar um código de status. É necessário observar método, headers, corpo, escopo do serviço e contexto de configuração. A experiência também mostrou como uma configuração inadequada pode expor informações desnecessárias e como limitar o diretório servido reduz essa superfície.
