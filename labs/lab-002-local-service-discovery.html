LAB-002 // LOCAL SERVICE DISCOVERY

ENCONTRAR. IDENTIFICAR.
VALIDAR.

Laboratório controlado para aprender como portas abertas e serviços podem ser descobertos e identificados com Nmap, usando exclusivamente um serviço criado localmente.

NMAPTCPHTTPPYTHONLOCALHOST

Objetivo

Criar um serviço HTTP local, validar sua disponibilidade e usar o Nmap para descobrir a porta aberta e identificar o software que está respondendo.

Ambiente

O experimento foi executado no Debian dentro do WSL, usando exclusivamente o endereço de loopback 127.0.0.1. Nenhuma rede externa foi alvo do scan.

ESCOPO

127.0.0.1 representa a própria máquina. O serviço foi criado deliberadamente para o laboratório.

Metodologia

  • Instalar e verificar o Nmap.
  • Criar uma página HTML local.
  • Iniciar Python SimpleHTTPServer na porta 8080.
  • Validar o serviço com curl.
  • Executar Nmap básico na porta 8080.
  • Executar Nmap com detecção de versão usando -sV.
  • Comparar as evidências produzidas pelas ferramentas.

Resultados reais

01 // CURL
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.13.5
Content-type: text/html
Content-Length: 66
02 // NMAP BÁSICO
PORT     STATE SERVICE
8080/tcp open http-proxy

999 outras portas TCP padrão não foram alvo deste teste específico.
03 // NMAP -SV
PORT     STATE SERVICE VERSION
8080/tcp open http SimpleHTTPServer 0.6 (Python 3.13.5)
04 // SCAN PADRÃO DO LOCALHOST
Not shown: 999 closed tcp ports (conn-refused)
PORT     STATE SERVICE
8080/tcp open http-proxy

Interpretação

O scan básico identificou a porta 8080 como aberta, mas inicialmente associou o número da porta ao serviço http-proxy. Com -sV, o Nmap realizou detecção de serviço e identificou corretamente o SimpleHTTPServer 0.6 executado pelo Python 3.13.5.

O curl forneceu evidência independente e confirmou a mesma identificação através do cabeçalho HTTP Server.

Conceitos aprendidos

  • open: existe um serviço aceitando conexões na porta.
  • closed: o host responde, mas não há serviço aceitando conexões naquela porta.
  • -sV: solicita detecção de serviço e versão.
  • Evidência cruzada: comparar Nmap e aplicação reduz interpretações erradas.

Conclusão

O LAB-002 demonstrou o ciclo básico de descoberta de serviços: criar um alvo conhecido, validar sua resposta, descobrir a porta com Nmap e confirmar a identidade do serviço com detecção de versão e evidência HTTP.
